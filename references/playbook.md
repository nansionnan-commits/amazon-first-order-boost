## 一、为什么是「首单」这个触发点

**一个品出第一个单，是它能活下来的第一个证据。**

在此之前：
- 不知道关键词选对没有
- 不知道价格带对不对
- 不知道主图有没有吸引力
- 不知道类目竞争强度

出第一单之后，上述至少有一项被市场确认了。这时候投广告/A+/视频，是在**已知有需求**的基础上放大，而不是拿钱试错。

**实测反例**（2026-10 数据）：刘冬冬 US/CA 14 天 0 单的品，同期烧了 $74.76 广告费，ACoS 全 ∞。这些品在出单前投广告，就是纯烧钱。

## 二、广告：先看有没有，再看要不要动

### 第一步永远是「查现状」

不要一上来就给建议。先确认：
1. 这个 ASIN 有没有广告活动？（`sp/campaigns/list` 按 ASIN 过滤）
2. 有的话什么状态？（ENABLED / PAUSED / ARCHIVED）
3. 日预算多少？bid 多少？出价策略是什么？

**很多"要不要开广告"的问题，其实是"已经有广告但没花钱"**，这时该查 `servingStatus`（可能是 `ACCOUNT_OUT_OF_BUDGET`），不是重新开组。

### 没广告时的建组规则

| 售价 | 类目月销中位 | 结构 | bid |
|---|---|---|---|
| ≥$20 | ≥100 | 1 AUTO + 1 MANUAL | $0.4 |
| ≥$20 | <100 | 1 AUTO + 1 MANUAL | $0.2 |
| <$20 | 任意 | **只 AUTO** | $0.2 |

**为什么低价品不开手动**：手动组要选词、要抢位，$10 的品 bid $0.4、点击 10 次出一单，ACoS 就已经 $4/$10 = 40%。加上退货和 FBM 运费，必亏。

**AUTO 的 bid 在 `adGroup.defaultBid`**，不在 keywords 里。改的时候容易漏。

### 已有广告时的拓词规则

拉近 14 天搜索词报表，逐个词判：

| 条件 | 动作 | 理由 |
|---|---|---|
| 出单 ≥2 且 ACoS ≤30% | 加精准组 / 提 bid | 已验证赚钱，值得放大 |
| 花费 ≥$2 且 0 单 | 精准否定 | 纯烧钱 |
| CTR ≥0.5% 且 CVR ≥5% | 提 bid 抢位 | 流量质量好，位置不够 |
| 曝光 ≥100 且 0 点击 | 精准否定 | 相关性差，白拿曝光 |
| 其他 | 观察 | 数据量不够 |

**ACoS 警戒线 30%**：超过说明广告在亏，但不要立刻停——先看是不是首单期（首单期 ACoS 高正常，因为还没有自然排名）。

## 三、A+：不是「有没有」的问题，是「标配」的问题

### 实测数据（2026-10-23，christmas wreath ties 类目，10 个竞品）

| ASIN | A+ | 视频 | 月销 |
|---|---|---|---|
| B09HGQ6BRB | ✅ | ✅ | 151 |
| B0DCNV6JWF | ✅ | — | 116 |
| B0CFQQ5MWV | ✅ | ✅ | 114 |
| B01LYFX6PX | — | — | 108 |
| B0FG84PFWH | ✅ | — | 100 |
| B0FFB32119 | ✅ | ✅ | 77 |
| B0HBB1VQRS | ✅ | — | 67 |
| B0FPCLPL73 | ✅ | ✅ | 51 |
| B0G1LV8Q14 | ✅ | — | 39 |
| B0FPF6TS7Q | — | — | 38 |

**A+ 率 80%，视频率 40%。**

注意月销最低的两个（39、38）恰好都没有 A+，而月销 100+ 的几乎全有。样本小不能下因果结论，但**同类目 8/10 有 A+，我们没有就是明显短板**。

### 7 模块的作用分工

| 模块 | 解决什么 | 常见错误 |
|---|---|---|
| banner | 第一眼印象 | 堆产品图，没有主张 |
| three_img | 三个核心卖点 | 五点直接复制，太长 |
| wide_banner | 使用场景 | 摆拍感太重，不像真实使用 |
| compare | 打消「为什么不买便宜的」 | 对比对象太弱，显得假 |
| specs | 尺寸/材质确认 | 漏掉关键尺寸导致退货 |

### 生图 prompt 的三条硬规则

1. **尺寸写死**：`aspect ratio 970x600 horizontal`
2. **产品占位写死**：`product on the LEFT two-thirds, clean negative space on the RIGHT third for headline`
3. **禁止项写死**：`no text, no logo, no watermark, photorealistic`

**不写第 2 条**，AI 会把产品摆中间，右侧没地方放标题，返回 Amazon 后台会被裁切。

**参考图必须传**：`aigc/imageGenAsync` 的 `images` 参数不能空。

## 四、视频：sellersprite 只告诉你「有没有」

### 字段位置

```json
{
  "badgeVideo": "Y",
  "badgeEbc": "Y",
  "badge": {"video": "Y", "ebc": "Y", "newRelease": "N", "amazonChoice": "N", "bestSeller": "N"}
}
```

两个地方都有，判的时候取并集（有时只有 `badge{}` 里有）。

### 抓不下来

Amazon 的视频地址在页面里是 JS 动态注入的，sellersprite 只给布尔值。
**要拿到视频文件，得单独解析商品页**（浏览器抓 DOM 或找 `<video>` 标签的 `src`），这是另一件事，不在本 skill 范围。

### 什么时候值得做视频

| 视频率 | 判断 |
|---|---|
| ≥50% | 标配，不做就是劣势 |
| 20-50% | 加分项 |
| <20% | 做了是差异化 |

**另一个维度**：看月销靠前的竞品有没有视频。如果 Top3 都有，说明这个类目买家吃视频，优先级要提。

## 五、动作卡的写法

每个首单品输出一张卡，**必须包含三块**：

```
## <SKU> — <store>-<market>
- ASIN / 首单价 / 首单日期

### ① 广告
现状（有没有、什么状态）→ 结论（开/不开/改什么）→ 具体参数

### ② A+ / 视频
badgeEbc / badgeVideo 实际值 → 同类目基准 → 结论

### ✅ 动作清单
- [ ] 可勾选的待办
```

**为什么要有动作清单**：老板看完不缺方案，缺的是「现在要做哪三件事」的清单。可勾选的形式能直接执行。

## 六、常见误解

| 误解 | 实际 |
|---|---|
| 「新品一上架就该开广告」 | 首单前投广告，ACoS 必然难看，且无法判断是广告有效还是自然流量 |
| 「A+ 是加分项，可以不做」 | 同类目 80% 有 A+，不做是短板不是「少个加分」 |
| 「有出单就说明没问题了」 | 出单可能是低价偶然，要看首单价格是否偏离目标价带 |
| 「视频率低说明不用做」 | 视频率低恰恰说明做了能拉开差距 |
| 「父体不 BUYABLE 是 bug」 | 父体无 offer，本来就不该 BUYABLE，正常 |
